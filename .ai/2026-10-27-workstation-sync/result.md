# Workstation sync — разбор

Дата: 2026-10-27.

## Решение

Окно сужается, git-синхронизация остаётся прежней. Удалить с экрана разбор Dart (виджеты, импорты, медиа-сканер, semantic index, Agent, редактор). Цикл `ContextSyncService` не менять: pull --rebase, diff деревьев, additive merge, при конфликте тех же путей — Cursor merge, коммит `sync: <uuid>`, push текущей ветки.

Сборки спрятать, не удалять, пока не подтверждено. Git/GitLab самих репозиториев приложение по-прежнему только читает.

## Опора

- `C:\Work\utilities\project_manager` — ~170 dart-файлов в `lib/`, `ContextSyncService` уже синхронизирует `.ai` через git.
- Сканера переводов чужих проектов нет. en/ru — строки самого приложения.
- `cursor-workstation-pack-20261022`: 578.6 МБ, 4434 файла. Полезный слой `.cursor` ~0.5 МБ. `projects-ai` 468 МБ, из них kiosk ~337 МБ мусора. Транскрипты ~50 МБ. `mcp-grafana.exe` 51 МБ.
- Секреты в паке: токены в `mcp.json`, Happ `subs.db`. В git их не класть.
- Память проекта: вкладка сборок только stage `build`; task id для `.ai` не спрашивать.

## Макет

Один экран: слева проекты и блоки машины, справа ветка, последняя задача, Pull/Push, четыре строки статуса. Конфликт — список файлов.

## Репозиторий

Текущий клон `context_sync_repo`, ветка `main`. В корне пять UUID, внутри зеркало `.ai`. Это дерево не перекладывается.

Профиль рабочего места — соседняя папка `settings/` в корне того же клона. skills, rules, memories и mcp.json копируются целиком, токены остаются. Не UUID: старый клиент копирует в `.ai` только каталог с именем `contextId`.

Фильтр больших файлов внутри существующих UUID выключен: он меняет дерево, которое вторая сторона уже забирает целиком.

## Сделано 2026-10-27

Фаза 1. `ProjectManagerState` на старте и по интервалу синхронизирует все проекты из `projects.json` по одному. Смена выбранного проекта не обрывает эту очередь. Ручная кнопка по-прежнему синкает только выбранный проект. Если pull падает из‑за сети, паузы 15 с, 30 с и 60 с, три попытки на проход.

Фаза 2. Второй запуск активирует окно `Project Manager` и выходит (`Local\ProjectManager`). `--minimized` показывает окно свёрнутым. В настройках тумблер «Запускать при входе в Windows» создаёт или удаляет задачу планировщика `ProjectManager` при сохранении. Путь к exe хранится в настройках, по умолчанию это exe текущего процесса.

Фаза 3. После очереди проектов в клон пишется `settings/cursor`: skills, rules, memories.json и mcp.json целиком, с токенами. Обратно на эту машину приезжает то, что добавил второй компьютер. Коммит только этой папки называется `sync: settings`. Папки UUID не трогаются. `settings.json` редактора не копируется. Собранный release при старте и раз в час смотрит `version_x.x.x.zip` в корне клона и заменяет себя, если версия новее. Debug этого не делает.

Экран. Режимы: Обзор, Папка .ai, Самоанализ, Git. Папка .ai показывает воспоминания, память агента и заголовки задач. Самоанализ читает отчёт из `agent-profile.json` и запускает тот же `runSelfAnalysis`. Каталог, в котором нет ничего кроме `.ai`, считается пропавшим. Синхронизация такой каталог не создаёт заново. В список вернулись три проекта из сохранённых карточек: kiosk-order-web, Toppen Киоск, Kiosk Cofix.

Синхронизация Toppen падала с `PathNotFoundException`: в `.ai` лежат пути длиннее 260 символов (`video_player/.../platformview`). Обход, копирование и удаление идут через префикс `\\?\`, недоступный каталог пропускается. Git-протокол не менялся.

Git / GitLab. Над списком изменений — активность за 26 недель: сумма коммитов и строк, столбцы по неделям, авторы с долей коммитов и строками `+`/`−`, восемь последних коммитов.

Крупные файлы. GitHub не принимает blob от 100 МиБ. `installed.apk` (160.69 МиБ) в клоне режется на `installed.apk_part_1` … по 95 МиБ и `installed.apk.pm-split.json`. В папке `.ai` проекта файл остаётся одним. Перед сравнением части собираются, перед коммитом снова режутся. Каталог `.git` не режется.

После ошибки. Старт, интервал и слежение за `.ai` не запускают синхронизацию, пока пользователь не нажмёт «Синхронизировать сейчас». Пропуск «папка проекта не найдена» паузу не ставит. Сетевой обрыв по-прежнему повторяется три раза внутри одного прохода и только потом ставит паузу.

## Порядок

Источник для продолжения: `PLAN.md` в корне. Кратко:

1. Автосинхронизация всех проектов на старте и по интервалу. Git-протокол тот же.
2. Один процесс и автозапуск через планировщик Windows, окно свёрнуто.
3. Папка `settings/` — полные копии skills, rules, memories и mcp.json с токенами. Проектные UUID не трогать. Happ и lan3 туда не класть.
4. Сузить окно. Cursor merge в протоколе синка оставить.
5. Приёмка. `legacy` остаётся на `0cf66e1`.
